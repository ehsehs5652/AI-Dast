# AI-DAST-ALL Recon/Attack 병합 기록

2026-09-23 기준 팀원의 **작업 트리**를 기능 원본으로 삼았다. 커밋 `15a8ee0`만으로는 작업 내용을 재현할 수 없으므로, Recon/Attack 및 직접 연동 파일 62개의 SHA-256을 [소스 매니페스트](AI_DAST_ALL_2026_09_23_SOURCE_MANIFEST.json)에 고정했다. 중첩 `AI-DAST-ALL/` 저장소 자체는 결과물에 포함하지 않는다.

| 기능 경계 | 병합 결정 | 현재 결과 |
| --- | --- | --- |
| Recon 경로 정규화와 동적 세그먼트 학습 | 적용 | 원본 `judgment.py` 동작을 가져왔다. 스트리밍 중 저장된 관측·매개변수·거래를 학습된 endpoint로 합치고, 반복 리다이렉트 경로는 발견 후보와 최종 surface에서 제외한다. |
| 쿼리와 매개변수 | 적용·조정 | 매개변수 메타데이터에는 값 없이 쿼리 시그니처와 이름·위치·타입·역할을 저장한다. 기존 HTTP 거래 원본 캡처 계약은 유지한다. 스키마에 열과 테이블을 추가하며 `Pipeline.db` v11을 내리지 않는다. Attack Skill 선택도 매개변수 역할을 읽는다. |
| SPA 탐지와 적응형 JS API 발견 | 적용·조정 | SPA/framework 신호는 수동 관측으로 남기고, API가 부족할 때 동일 출처의 제한된 JS 후보를 조사한다. 후보는 응답한 없는 경로의 대조군과 비교하고 HTML 대체 페이지를 제외한다. 정책 프록시 없이 정책 대상 요청을 시작하지 않는다. |
| 와일드카드 호스트 상태 | 적용 | 발견 호스트의 생존 탐색 결과를 `unknown/active/dead`로 별도 보존하고, 탐색 시간을 제한한다. |
| 프록시 요청 예산 | 적용 | 메서드·출처·경로 외에 원래 순서의 쿼리/본문 해시를 중복 판정에 포함해 서로 다른 요청을 합치지 않는다. |
| Attack Skill 선택 | 기존 구현 보존·확장 | 원본의 SPA/API Skill 신호는 이미 현재 선택기에 있었다. 새 Recon 매개변수 역할만 연결했다. |
| Attack 실행·승인·증거 | 기존 구현 보존 | 원본 Attack 테스트가 현재 구현에서 통과했다. 현재의 서명된 승인, 실행/세션 격리, 시도와 증거 연결, Validation 재현 계약을 유지했다. |
| Recon 정책·대상 모델 | 현재 계약 유지 | 원본의 상태 변경 메서드 허용과 이전 대상 모델은 현재 Scope/Auth 계약과 충돌한다. 현재의 GET/HEAD/OPTIONS 제한과 `target_id` 기반 대상을 유지한다. |
| `completed_with_errors` Recon | **보류** | 원본은 일부 실패한 전체 scan도 Attack에 전달하지만, 현재 저장된 작업 기록은 실패한 작업과 관측 대상을 검증 가능하게 연결하지 않는다. 선택 대상의 완전성을 증명할 수 없어 현재의 완전한 scan 요구를 유지한다. 추후 작업별 대상·관측 출처를 영속화하고 검증된 부분집합 handoff가 필요하다. |
